title: llms.txt
description: The plain-Markdown rendition of the API surface, and how to advertise it to starlight-llms-txt.

Each documented package serves its whole API surface as plain Markdown at `<base>/llms.txt`, for
example [/api/demopkg/llms.txt](/starlight-pydocs/api/demopkg/llms.txt). It is on by default; set
`llmsTxt: false` to drop the endpoint.

The point is that a language model reading documentation does better with one dense Markdown file
than with a crawl of rendered HTML, and the same file happens to be a good diff target: it is the
format the package's own unit tests snapshot, so a change in the rendered surface is a change in
this file.

## What it contains

A short header naming the package and pointing at the rendered pages, then every page of the
package in navigation order:

````md
# demopkg

> API reference for the Python package `demopkg`, generated by starlight-pydocs.
> Rendered pages: https://ewels.github.io/starlight-pydocs/api/demopkg/

# demopkg

_module_

Demo package used by the starlight-pydocs test suite.

## demopkg.Report

_class_

```python
class Report(BaseReport)
```

Bases: `demopkg.report.BaseReport`

Re-exported from: `demopkg.report`

[View source](https://github.com/ewels/starlight-pydocs/blob/main/fixtures/demopkg/src/demopkg/report.py#L57-L160)

A named collection of scored sections.

**Parameters**

- `name` (`str`) — Human readable report name, also used as the file stem.
- `scores` (`dict[str, float] | None`) (default: `None`) — Mapping of metric name to score.
````

Every object gets its dotted path as a heading, at the depth the rendered page uses, its kind and
labels in italics, its signature in a `python` fence, its provenance, and every docstring section as
Markdown. Doctest blocks are fenced as `pycon`. Source links are included as links. Docstring prose
is passed through as written, so [cross-references](/starlight-pydocs/guides/cross-references/)
appear in their `[title][dotted.path]` form, which is more useful to a model than a resolved URL.

Because it is prerendered as a static file, a static host serves it as `text/plain` regardless of
the `text/markdown` the route sets. Browsers show it, `curl` pipes it, models read it.

## With starlight-llms-txt

[starlight-llms-txt](https://delucis.github.io/starlight-llms-txt/) builds a site-wide `llms.txt`
from the `docs` content collection. Injected routes are not part of that collection, so it cannot
see the generated API pages — but it can advertise ours, through its `optionalLinks` option:

```js
// astro.config.mjs
import starlight from '@astrojs/starlight';
import { defineConfig } from 'astro/config';
import starlightLlmsTxt from 'starlight-llms-txt';
import starlightPydocs, { pydocsSidebarGroup } from 'starlight-pydocs';

export default defineConfig({
  site: 'https://docs.example.com',
  integrations: [
    starlight({
      title: 'mypkg',
      plugins: [
        starlightPydocs({ packages: [{ name: 'mypkg', search: ['../src'] }] }),
        starlightLlmsTxt({
          optionalLinks: [
            {
              label: 'mypkg API reference (Markdown)',
              url: 'https://docs.example.com/api/mypkg/llms.txt',
              description: 'Every documented module, class, function and attribute in mypkg.',
            },
          ],
        }),
      ],
      sidebar: [{ label: 'API reference', items: [pydocsSidebarGroup] }],
    }),
  ],
});
```

`optionalLinks` entries take `label`, `url` and an optional `description`, and appear under an
`## Optional` heading in the generated `llms.txt` — links a model may follow when it wants more than
the prose. Use absolute URLs: that file is read by clients that have no notion of your site's base.

## Consuming it yourself

The endpoint is a normal prerendered file, so anything can read it:

```sh
curl -s https://docs.example.com/api/mypkg/llms.txt > mypkg-api.md
```

If you want the same information as structured data rather than Markdown — to build a table, a cheat
sheet or your own index — use the
[Content Layer loader](/starlight-pydocs/guides/vanilla-astro/#the-content-layer-loader), which
exposes one entry per documented object with its path, kind, brief, signature and page.
