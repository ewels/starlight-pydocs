---
title: Source links
description: Link every documented object to the lines it is defined on, with a forge preset or a URL template.
---

Every object Griffe found carries its file and its first and last line, so each one can link
straight to its source. Configure it per package with a forge preset:

```js
packages: [
  {
    name: 'mypkg',
    search: ['../src'],
    sourceLink: { host: 'github', repo: 'you/mypkg', ref: 'main', root: '..' },
  },
];
```

`host` is one of `github`, `gitlab` or `bitbucket`, and `repo` is the `owner/name` slug. The
presets expand to:

| `host`      | URL shape                                                        |
| ----------- | ---------------------------------------------------------------- |
| `github`    | `https://github.com/{repo}/blob/{ref}/{path}#L{start}-L{end}`     |
| `gitlab`    | `https://gitlab.com/{repo}/-/blob/{ref}/{path}#L{start}-{end}`    |
| `bitbucket` | `https://bitbucket.org/{repo}/src/{ref}/{path}#lines-{start}:{end}` |

`ref` defaults to `main`. Point it at a tag to pin the links to a release, or at a branch to keep
them current.

## A template of your own

Self-hosted forges, Gitea, Sourcehut, an internal code browser: give a template instead of a host.

```js
sourceLink: {
  template: 'https://git.internal.example/mypkg/-/blob/{ref}/{path}#L{start}-L{end}',
  ref: 'v2.1.0',
  root: '..',
}
```

| Placeholder | Value                                                        |
| ----------- | ------------------------------------------------------------ |
| `{path}`    | Path of the file the object is defined in                     |
| `{start}`   | First line of the object                                      |
| `{end}`     | Last line of the object, or the first when griffe knows only one |
| `{ref}`     | The `ref` option                                              |

`{path}` is required: a template without it is a configuration error, because a link to a whole
repository is not a source link. The other placeholders are optional; drop the line fragment if
your browser does not do line anchors. Paths always use forward slashes, whatever the build ran on.

## `root`, and why you probably need it

Griffe reports file paths relative to the directory it ran in, which is the Astro project root.
That is repository-relative only when the two are the same directory. A documentation site in
`docs/` with its Python sources one level up therefore gets paths that are not
repository-relative. When the sources are outside the project entirely, the paths are absolute.

`root` names the directory `{path}` should be computed against, itself relative to the Astro
project root:

```js
// Repository layout:
//   src/mypkg/…      the Python package
//   docs/            this Astro project
sourceLink: { host: 'github', repo: 'you/mypkg', ref: 'main', root: '..' },
```

With `root: '..'`, `{path}` becomes `src/mypkg/report.py`, which is what the forge expects. Without
it, the link would point at `mypkg/report.py` or carry the absolute path of the machine that ran
the build.

The rule of thumb: set `root` to your repository root whenever the Astro project is a
subdirectory. This documentation site does exactly that.

## What renders

Each documented object gets a `View source` link next to its heading, with the file and line range
as the link's `title`:

```html
<a class="pyd-source-link" href="https://github.com/you/mypkg/blob/main/src/mypkg/report.py#L57-L160"
   title="src/mypkg/report.py:57-160">View source</a>
```

The label comes from the `viewSource` string, so it follows the site's locale and can be replaced
per component with `labels={{ viewSource: 'Source' }}`.

## Without any configuration

Griffe 2 records a `source_link` per object: a blob URL at the commit it extracted from, derived
from the repository's own git remote. When no `sourceLink` is configured, that link is used as-is.
It is convenient and it needs nothing from you, with two caveats: it is pinned to the commit that
was checked out when the dump was made, and it only exists when griffe ran inside a git checkout
with a recognisable remote, so a pre-generated dump from someone else's CI may or may not carry
one.

Configure `sourceLink` when you want links that follow a branch or a tag, or when you want them to
point somewhere other than the remote griffe happened to see.

:::caution[Set `root` even when you rely on the fallback]
The href from griffe's own `source_link` is always fine, but the link's `title` is built from the
path griffe reported. Without `root`, that title can carry the absolute path of the build machine.
:::
